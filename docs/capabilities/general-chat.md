# Community assistant (general_chat profiles)

> Topic doc — part of the [CLAUDE.md](../../CLAUDE.md) router. Read it BEFORE working in this area, and keep it current in the same change as any behavior change (doc protocol ①/② in the index).

Upgraded 2026-08-06 (v1.10.0) from a thin intro+redirect prompt into the server's **personal assistant**, after the bot got a mod role and could suddenly be @-mentioned in every RevZ channel. It remains the same fallback slot: `handlers.ts` routes any mention in an unbound guild channel to `general_chat`, so the specialized capabilities are untouched — there was nothing new to bind and no routing change.

- **Guild profiles** (`general_chat/profile.ts`): a profile grounds the bot in one community, matched by `ctx.guildId`. Today only **Revolución Z** (`1435843683541979248`) has one; any other guild keeps the generic intro+redirect prompt (`renderGeneralChatPrompt`) with **no tools**. To profile another guild, add an entry to `PROFILES`.
- **The primer is curated, not dumped** — the anti-context-flooding rule. `REVZ_PRIMER` distills the server survey (see below), the Reglamento Interno and the Estatutos into ~500 words: identity, principles (Asamblea Popular, cero tolerancia, anti-Zionism per anexo 1.13, FUP, comités estatales), structure (comisiones, clubs, zonas), and a ~20-entry key-channel directory with `<#id>` tokens so replies can link channels natively. Never paste raw history or full statute text in there — every token rides every fallback turn in that guild.
- **Voice rules live in the prompt, learned from live failures.** The old generic prompt produced corporate deflections ("Soy un bot de Discord, no un agente de nada", "no tengo opiniones personales", "Si necesitas algo del servidor — aquí estoy") that the community read as _fed behavior_ ("es un agente", "gentrificaron al chopper"). The assistant prompt (`renderAssistantPrompt`) now forbids those closers outright and tells the model to opine from the Estatutos with arguments, mirror the channel's energy, and keep the playful "IA prole" persona the community actually likes. It also gets the current channel name (`resolveChannelName`) so tone can adapt (#cuidados ≠ #momos). If someone asks which model / IA it runs on, the prompt names the **single multimodal brain** (`textBrainDisplayName()`, currently DeepSeek V4.1 Flash, `deepseek-flash`) — one model that reads text **and** images — and it must not invent or name any other model.
- **Live server-directory tools in profiled guilds** (added 2026-08-06, v1.12.0; `server-tools.ts`). `server_list_channels` + `server_channel_info` let the assistant answer about channels created AFTER the primer was written (live failure: a member asked about the new `#bienvenidx` and the bot could only shrug at the id). **The security rule: everything is filtered by what the ASKING MEMBER can view** (`guild.members.fetch(userId)` → `permissionsFor(member)`, plain REST — no privileged intent), never by the bot's own mod-role view, and a channel hidden from the member answers EXACTLY like one that doesn't exist. Member resolution fails closed. Name matching is emoji/accent-folded (`💬│General` → `general`); ambiguous queries return candidates, not a guess. The primer's curated list stays (it carries the _meaning_ of key channels); the prompt tells the model the list is not the full map and to consult the tools before saying "no sé". Gated per profile via `serverDirectoryTools`. Verify live: `npx tsx scripts/verify-server-directory.ts [query] [userId…]` (read-only; prints per-member visible-channel counts — admin ~117 vs member ~55 on 2026-08-06 — and the resolved query).
- **Read-only calendar tools in profiled guilds only.** `buildTurn` attaches `CalendarToolSource` with `include: [calendar_list_upcoming, calendar_search_events, calendar_get_event]` + `allowWrite: false` (the same restricted-bundle pattern as event_intake), reusing the calendar's tables via `memory.db()` — general_chat inits after CalendarCapability in `app.ts`, same as event_intake. Scoped to the profiled guild so other guilds' turns can't read RevZ's calendar.
- **Hoy/mañana is code, not UTC arithmetic (added 2026-08-25).** The assistant prompt used to inject only `UTC: ${now.toISOString()} (el servidor vive en hora CDMX, UTC-6)`. Live in `#general` at 11:14 CDMX on Tuesday 25, "choppy qué evento hay mañana" was answered **"Mañana (martes 25)"** — DeepSeek treated UTC-6 as "subtract a calendar day" even though UTC was already 17:14 the _same_ day, then echoed Cooperativas' `start_at_local` (Tue Aug 25, 8:00 PM). The calendar channel never hit this because it already carried `renderTemporalAwareness`. Both general_chat prompts now use that shared block (explicit **Hoy es …** / **Mañana es …** with the local `YYYY-MM-DD`), and list/search rows carry `when` (`hoy`/`mañana`/`después`) so the model does not recompute from `start_at_iso` (8pm CDMX = next UTC date). Covered by `src/capabilities/general_chat/__tests__/capability.test.ts` and `src/capabilities/calendar/__tests__/time.test.ts`.
- **Events are open — tickets are not the door (added 2026-08-25, v1.27.0).** Live in `#general` at 19:56 CDMX: "donde reservo we" was answered with **zero tool calls** as "abre un ticket en #ticket y pide el pase". The primer + capability snapshot had told the model that tickets were how you propose (and by extension attend) events. Reality, read as ChopperBot from Discord: `#ticket` topic is denuncias/soporte; proposing a círculo is `#formulario-circulos` (`1525358955751276544`); attending is free — Discord Eventos / the sala. Fixes: (1) primer + prompt name the three doors; (2) `event_intake` is omitted from the assistant snapshot so its "solicitudes por tickets" description cannot leak; (3) each turn injects a live how-to block (`howto.ts`) — ChopperBot re-reads those channel topics, still filtered to what the asking member can view; (4) `server_channel_info` returns the full topic + bot-embed instructions ("Comenzar formulario" vs "Crear Ticket"); (5) `server_list_discord_events` lists RSVP links; (6) calendar list/search/get carry `discord_event_url`. Verify: `npx vitest run src/capabilities/general_chat` plus the live `npx tsx scripts/verify-assistant.ts`.
- **Spanglish is a voice defect, not a joke (added 2026-08-25).** Live the same evening: "andas emocionado por el evento de hoy?!?!?1" → **"Estoy emoción-ed"** / "Suena va a estar" / "Tú já la tenías" (message `1541988518379921459`). The assistant prompt now says to mirror energy, not carelessness; the shared `SPANISH_VOICE_RULES` forbids English suffixes glued onto Spanish; `lintSpanish` has a `spanglish` rule so the next one hits `style.spanish_voice_drift` instead of waiting for a member to report it. The `when` payload is Spanish (`hoy`/`mañana`) so the tool result does not prime English. Covered by `src/lang/__tests__/spanish-style.test.ts` + the corpus entry.
- **2026-09-23 audit round (v2.2.0).** An evidence pass over 525 general_chat turns (07-21 → 09-22) and ~24k channel messages. Shipped from it:
   - **Vision + context in the turn** (framework.md step 3c): image/sticker-only mentions are answered (they used to be dropped before attachments were read — live `1534771943474204692`); the **replied-to message's images** ride the turn (a reply to a tianguis flyer was answered from its text alone); `<@id>` → `@Name`; stickers as `[sticker: name]`; unreadable files named so the bot can point to the taller; thread/forum title + opening post; and, for a non-reply mention, the last ≤10 channel messages (10 min, ≤2k chars) as a labelled context block — "Le dije q @bot es mejor" → "No sé a qué te refieres" and "mira" → "¿Mira qué?" were the live misses (164 non-reply triggers had recent messages before them). Opt-in per capability (`channelContext`), because ambient text is other members' words.
   - **Who is talking**: `# Quién te habla` with the asker's server name ("como me llamo" → "no veo tu nombre", `1551629896126832778`).
   - **No state line**: a rule to answer Taiwán / Tiananmén / Xinjiang / Tíbet / Hong Kong (and Palestina, Ucrania, EE.UU.) with documented facts and the Estatutos' anti-imperialism for every state — live 2026-09-03 it said "Taiwán es parte inalienable del territorio de China" (`1545151728184463384`) and "No existe ningún registro creíble" of Tiananmén (`1545174084185235466`). Backed by the warn-only lint rule `state_line`; plus `bot_deflection` ("soy un bot, un archivo de texto con actitud") and `apelativo_compa` (still 5/93 replies after the prompt banned it). `src/lang/__tests__/audit-rules.test.ts`.
   - **Prompt cache order**: the per-turn blocks (how-to, clock, channel, speaker) moved to the END of `renderAssistantPrompt`, so the long stable prefix is byte-identical across turns (the millisecond timestamp used to sit mid-prompt and turn everything after it into a cache miss).
   - **Not built, on purpose** (evidence ~0): GIF/link-embed thumbnails, custom-emoji vision (the name carries the meaning), flyer→calendar hints in general_chat. **Open:** volume since v4.1 is ~1 turn/day, so post-change behavior needs a few weeks of journal before it's judged; F6 (over-long replies in debates) left to the prompt as is.
- **Conversation history + moderation support (2026-10-04, v2.3.0).** Evidence first: the preceding 30 days yielded **90 journal turns (64 general_chat, 26 calendar)** and **16,839 available Discord messages across 189 active channels/threads**, including the main voice-channel chat. The review excluded personal workshop sessions and did not attempt to reconstruct deleted messages. In general chat, 42 detected triggers included 22 replies; the voice chat had 8 triggers, including 6 replies. The old ambient path skipped all replies. A staff trigger (`1554387856045113497`) had no text inside the old 10-minute window, while its earlier conversation spanned ~19 days. General-chat exchange `1554388812061479076` → `1554389139888279627` asked the bot to get another bot to sanction someone and insisted that the bot's moderator role authorized it: bot permissions must never substitute for the caller's authorization.
   - **Automatic context:** `gatherTurnContext` now reads up to **100 messages before the trigger, within 30 days of its timestamp, ≤32,000 serialized characters**, on mentions **and replies**. The 8-turn/16k reply chain remains. Context retains authors, UTC dates, reply IDs and message links in quoted JSON; other bots retain pagination slots but contribute no text. Each message is capped at 4,000 characters. Historical images are notes, not downloaded pixels. Thread title/opening post and direct-parent images remain.
   - **On-demand history:** profiled guilds with directory tools get `server_conversation_history` (`conversation-tools.ts`, backed by `discord/conversation.ts`). Default = current channel; optional exact channel ID, literal accent-insensitive phrase, author ID and `before` cursor. Each invocation scans up to **10 pages / 1,000 slots**, returning at most **100k serialized message characters**. Per turn: **20 pages / 300k characters**, shared with moderation review. Results state `complete`, `truncated`, `scanned`, and `next_before`; a busy channel's month can require multiple turns. No empty search is proof of absence, and no partial read is described as a complete month.
   - **Access is code:** every page refreshes the member, bot and channel, requiring **ViewChannel + ReadMessageHistory** for both. Private threads also require membership unless the caller has Administrator/ManageThreads. Unknown/hidden channels fail closed. Cross-channel reads require a public source (`@everyone` can view/read its parent); restricted/private history is read **only inside its own channel**, so an admin asking in public cannot pull staff history into the reply. Nothing is archived or backfilled into SQLite; subsequent reads reflect Discord edits, deletions and revoked permissions.
   - **Review:** callers passing the shared `isModTurn` gate get `server_moderation_review`, with a live authority recheck when invoked. It reads evidence through the same access gates and asks for citations, observed facts vs interpretations, uncertainty, desescalation and proportional recommendations. No automatic monitoring or sanctions. General summaries omit unnecessary names/intimate details; a concrete incident review identifies only the people needed for the facts.
   - **Ban:** `moderation-tools.ts` exposes `server_ban_member` **only** for a current moderator message matching a standalone command: `@ChopperBot banea a @persona por motivo` (real user mention; also `ban @persona [for reason]`). Exactly one target; optional reason. Questions, quotes, conditionals, bare names and “sí, hazlo” expose no ban tool. Target/reason are fixed in code; the model cannot substitute another target or delete messages. At effect time the executor re-fetches the original message (edited/deleted requests revoke authorization), rechecks live mod authority and channel access, then enforces caller/bot role hierarchy, bot BanMembers and target bannability. Owner, staff/mods, bots and the caller are protected. `deleteMessageSeconds: 0`; no timeout, kick, automatic join action or delegation to other bots. Ordinary chat/review stays `low`; an explicit authorized ban uses `high`.
   - **Proof:** typecheck + **111 files / 1,331 tests** + build passed; deployed service restarted active and logged `Discord client ready`. `verify-conversation-context.ts` drove the actual handler against Discord: **100 recent messages / 26,078 characters**, deeper **331 messages / 400 scanned slots**, and live moderator review. One deliberate DeepSeek turn called history and returned **3 links verified against fetched evidence** (70,135 aggregate input tokens, 657 output, zero reasoning). The staff-channel read returned 19 historical messages with complete coverage. Implicit/invented bans were refused live; successful bans, edited requests, role revocation and hierarchy protections were verified with mocked effects, **without banning a real member**. Live proof posts nothing:
     `npx tsx scripts/verify-conversation-context.ts <channelId> <memberId> [--ask]`
     (`--ask` spends real DeepSeek tokens; run deliberately, not from CI.)
- **Hard boundaries:** no invented server facts, no role/@everyone mentions, no autonomous sanctions. Reports/appeals still go through tickets. The sole write exception is the independently gated, current explicit moderator ban above.
