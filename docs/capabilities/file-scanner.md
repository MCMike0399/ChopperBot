# File scanner capability (VirusTotal)

> Topic doc — part of the [CLAUDE.md](../../CLAUDE.md) router. Read it BEFORE working in this area, and keep it current in the same change as any behavior change (doc protocol ①/② in the index).

Added 2026-07-03 (v1.1.0). Automatically scans file uploads with the VirusTotal public API v3 and posts a Spanish verdict card (✅ limpio / ⚠️ sospechoso / 🛑 malicioso). Inspired by `bananensplit/VirusChecki` but fixes its crude fixed-`sleep(25)` rate handling with a real serialized queue + hash-first lookup. Lives in `src/capabilities/file_scanner/`.

**What gets scanned (v1.26.0).** Images are skipped everywhere (quota; the vision path already understands them). **Audio is always scanned.** **Videos depend on the channel:** conversation channels (`#💬│general`, `#🎲│fuera-de-tema`, cuidados, zone chats, …) scan `.mov`/`.mp4`/etc. because a clip there is unusual; **media-native** channels (multimedia-general, momos, arte, videoclub, música, cineclub, galería, video-agitprop) skip genuine videos to keep the free-tier budget for documents and odd files. A video whose first bytes are _not_ video/audio (a `clip.mov` that is actually an exe) is scanned even in media channels (`isMediaDisguise` in `classify.ts`, Range-peek of 256 bytes). Files over VirusTotal's ~32 MB upload cap but under `VIRUSTOTAL_MAX_DOWNLOAD_BYTES` (50 MB) are still hashed and looked up; unknown ones render `too_large` with the SHA-256 so a human can check VT. Empty files and anything above the download cap are skipped. Count capped at `MAX_ATTACHMENT_COUNT`. Skip reasons other than "image" log `file_scanner.watcher.skipped` so a silent miss is triagable.

- **Passive, not routed — the exception to one-capability-per-channel.** It is registered in `app.ts` like the others but **never appears in the routing table**; instead `start()` attaches its own `client.on(Events.MessageCreate, …)` listener (because `app.ts` runs `start()` on every _registered_ capability regardless of bindings). So scanning coexists with chat/calendar/IG in the same channel. `buildTurn()` returns only a help preamble and is effectively unused. **Self-disables** (throws in `init()` → not registered) when `VIRUSTOTAL_API_KEY` is unset — mirrors the IG-without-cookies degrade; the log line is `file_scanner disabled: VIRUSTOTAL_API_KEY not set`.
- **Watched channels** are the capability's own setting (`file_scanner_settings`, single row), seeded once from `FILE_SCANNER_CHANNEL_IDS` on first boot (JSON array or comma/space list), DB wins after. The listener reads the set through a **10 s TTL cache** (`isWatched()` / `isMediaNative()`) so it doesn't hit SQLite on every message but still picks up `config_filescanner` edits within ~10 s (no restart). Besides plain channel ids the set accepts two **wildcards** (added 2026-07-03): `all` (every channel the bot can see, across all guilds) and `guild:<guildId>` (every channel it can see in that one guild). Because Discord only delivers `MessageCreate` for channels the bot has access to, these naturally mean "everywhere ChopperBot can read" — new channels are covered with no list to maintain. The live deployment watches `guild:1435843683541979248` (Revolución Z); other guilds the bot is in are deliberately NOT scanned. Set it from the config channel with `config_filescanner action:set_channels channels:"este servidor"` (keyword resolves to the caller's guild), `channels:"todos"` (→ `all`), or an explicit id/`guild:` list.
- **Media-native denylist** (added 2026-08-20, v1.26.0): `file_scanner_settings.media_channels_json`, seeded from `DEFAULT_MEDIA_NATIVE_CHANNEL_IDS` in `media-channels.ts` (or `FILE_SCANNER_MEDIA_CHANNEL_IDS` if set) on first boot after the v2 migration. Threads/forum posts inherit the parent channel's policy. Empty list = scan videos in every watched channel. Live seed: `#🖼️│multimedia-general`, `#😹│momos`, `#🫀│arte`, `#📽️│videoclub`, `#🎵│música`, `#🏴‍☠️│anime-y-manga`, `#📽️│chat-cineclub`, cineclub `#🗳️│votaciones` + cartelera, `#🖼️│galería-de-artistas`, `video-agitprop`. Tune live with `config_filescanner action:set_media_channels`.
- **The rate-limit design (the whole point).** VirusTotal free tier = **4 req/min, 500/day, ~32 MB/file**. Three layers, all in `rate-limiter.ts` + `store.ts`:
   1. **SHA-256 hash-first** (`scanner.ts`): hash the bytes, check our own `file_scanner_scans` cache (zero VT calls on a repeat), then `GET /files/{sha256}`. VirusTotal already knows most files → **instant verdict, no upload, no polling** (the EICAR smoke returns 66/68 malicious in one call). Only a 404 triggers `POST /files` + polling `GET /analyses/{id}` up to `VIRUSTOTAL_MAX_POLLS` (8). Files over `VIRUSTOTAL_MAX_FILE_BYTES` skip the upload and surface `too_large` if the hash is unknown.
   2. **Global serialized queue** (`ScanRateLimiter`): a single promise-chain mutex — one VT call in flight at a time, each spaced ≥`VIRUSTOTAL_MIN_REQUEST_INTERVAL_MS` (16 s, i.e. under 4/min). A burst of uploads drains politely instead of tripping VT's own 429s. Bounded queue depth (`QueueFullError`) sheds load. Clock + sleep are injectable → tests use a fake clock (no real waiting).
   3. **Persistent rolling-24 h budget** (`tryConsumeBudget` in the store, `VIRUSTOTAL_DAILY_REQUEST_BUDGET` default 480, headroom under 500): every VT call reserves a slot atomically; on exhaustion the limiter throws `BudgetExhaustedError` → the scan reports `budget_exhausted` and the user gets a polite "try later". Timestamps live in `file_scanner_runtime.request_times_json`, so the budget survives restarts (unlike the IG in-memory window).
- **Friendly messages** (`format.ts`, `watcher.ts`): react 🔬 on the upload, post ONE reply listing each file (⏳ en cola → 🔬 analizando → verdict), edited in place as each file resolves. A 🛑 malicious verdict appends an `@here` mod ping. Never deletes the message or file (warn-only, by design). Filter is `planScans()` (async, tested) — images via `isTrustedImage()`, videos via `isVideoAttachment()` plus optional magic peek; see "What gets scanned" above.
- **Send-permission guard (added 2026-07-05, v1.2.1) — the thread/forum gotcha.** `handleMessage` checks `canPostVerdict()` **before** reacting or spending a VT budget call: in a thread/forum post (`channel.isThread()`) the bot needs **`SendMessagesInThreads`**, a permission DISTINCT from `SendMessages` (granting only the latter still can't reply inside a thread/forum). A positive denial logs `file_scanner.watcher.cannot_send {channelId,guildId}` and returns early — no wasted scan, no confusing react-then-unreact. Uncertainty (DM, or member/perms unresolvable) never blocks. The initial post also degrades gracefully via `postInitial()`: a reply-with-reference also needs `ReadMessageHistory`, so if `message.reply()` throws it logs `…reply_failed` and falls back to a plain `channel.send()` (logging `…send_failed` if that also fails). This replaced the old silent `.reply().catch(() => null)` that swallowed permission errors — the symptom was "reacts 🔬 then un-reacts, posts nothing" in a channel where the bot could react but not send (e.g. the `📕│biblioteca` forum lacking `SendMessagesInThreads`).
- **Admin surface** (config channel): `config_filescanner` (`src/capabilities/configuration/filescanner-admin-source.ts`, registered in `configuration/capability.ts`) with `action`: `status` (enabled? watched channels, media-native channels, 24 h budget used/remaining, cache verdict counts), `list_channels`, `set_channels {channels}` (replace the watched set; empty string clears), `list_media_channels`, `set_media_channels {channels}` (replace the video-skip denylist; empty = scan videos everywhere), `scan_stats` (recent verdicts). Budget-exhausted / bad-API-key events also `sendAdminAlert` to the config channel, deduped 1 per 6 h.
- **Verify:** `npx vitest run src/capabilities/file_scanner` (store/limiter/scanner/format/classify — mocked client + fake clock, no network) and the **live smoke** `npx tsx scripts/virustotal-smoke.ts` (gated on real `VIRUSTOTAL_API_KEY`, NOT in `pnpm test`; scans a novel random file to exercise upload+poll, then EICAR to prove the instant hash path + 🛑 wording; prints budget used). Manual: drop a `.mov` in `#💬│general` (should 🔬→verdict) vs `#🖼️│multimedia-general` (should stay quiet, `file_scanner.watcher.skipped reason:video` in the journal).
