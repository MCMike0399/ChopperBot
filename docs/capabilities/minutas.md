# Minutas capability (voice-meeting recorder → AI minutes)

> Topic doc — part of the [CLAUDE.md](../../CLAUDE.md) router. Read it BEFORE working in this area, and keep it current in the same change as any behavior change (doc protocol ①/② in the index).

Added 2026-08-16 (v1.22.0). The Teams-style meeting minutes: a mod runs **`/chopperbot-join`** inside a voice/stage channel, the bot joins, records **each speaker separately**, captures the channel's **text chat**, and on **`/chopperbot-leave`** (or when the channel empties / the scheduled event ends / the max-duration backstop hits) it transcribes locally with **whisper.cpp**, builds a merged timeline draft, asks the text brain for the acta, and posts it to **#📜│minutas-de-asambleas** (`1503986918784766072`). Lives in `src/capabilities/minutas/`.

- **Passive, NOT routed** (fourth exception to one-capability-per-channel, like file_scanner/event_intake/workshop). Registered in `app.ts`, never in the routing table; `start()` attaches its own listeners: `InteractionCreate` (the two slash commands), `MessageCreate` (chat capture — only while a session is active on that channel), `VoiceStateUpdate` (auto-end), `GuildScheduledEventUpdate/Delete` (auto-end). The main mention handler is NOT claimed away: a voice channel's chat keeps working normally with general_chat.
- **Authorization = moderation tier**: `isModCaller` uses `modRoleTokens`, independently of calendar/event approval. Gestión alone cannot start or stop a recording. Bots never qualify; unresolved authority fails closed with an ephemeral denial. This captures voices only under a current moderator request.
- **Slash commands, guild-scoped**: `chopperbot-join [titulo]` / `chopperbot-leave`, registered per-guild at `start()` (`guild.commands.set` — instant propagation; replaces only THIS app's commands). Join requires the caller to be **in** a voice/stage channel (that's the channel recorded), an output channel configured, and no other active session in the guild. The 🔴 **recording notice posts to the voice channel's own chat** — consent is not optional.
- **Speaker separation is Discord's, not diarization**: the voice gateway already delivers one Opus stream per user — `receiver.speaking.on('start')` → `subscribe(userId, { end: AfterSilence 1.5 s })` → one **burst** per speech turn. Ordering matters and is correct: the receiver calls `speaking.onPacket()` _before_ looking up the subscription, so `onSpeakStart` subscribes synchronously and the first packet of a burst is never lost (`SpeakingMap.DELAY` is 100 ms, well under `SILENCE_END_MS`).
- **Decoding is NATIVE libopus (`@discordjs/opus`), packet-by-packet — do not revert to prism-media/opusscript.** Each packet is decoded inside a `try/catch` in `recordOpusStreamToPcm`, so a bad packet costs 20 ms; a run of `DECODER_REBUILD_AFTER_ERRORS` (5) consecutive failures replaces the decoder instance. ffmpeg then resamples 48 kHz stereo → 16 kHz mono **raw PCM** (`audio/NNN-<speaker>.pcm`). PCM is headerless on purpose: a crash mid-burst leaves a fully usable file; the WAV wrap (`pcmToWav`) happens at finalize time. **Receiving requires `selfDeaf: false` + `@snazzah/davey`** (Discord voice is E2EE/DAVE now) + the **`GuildVoiceStates` intent**. Decryption is `aead_aes256_gcm_rtpsize` via `node:crypto` — no sodium package needed, confirmed live.
   - **Why native (2026-08-17 fix, root-caused by reproduction):** `opusscript` is pure WASM and allocates inside a **fixed** WASM linear memory that must be freed with `.delete()`. prism-media only does that from `_destroy()`, which the old `pipe()`-based recorder never reliably triggered → one leaked decoder per burst. Measured ceiling: **~55 un-freed decoders**, after which `RuntimeError: memory access out of bounds` is thrown by **every allocation process-wide, including brand-new decoders** — unrecoverable without a restart. This silently killed capture 233 bursts into the 2026-08-16 assembly (22 bursts / ~3 min of audio lost while recording _appeared_ fine). Native libopus uses the ordinary process heap: verified to keep decoding after 20k mixed good/bad packets and 80 sequential bursts. `opusscript` was **removed from the dependency tree** so it cannot be reached as a silent fallback; `@discordjs/opus` must build from source (`pnpm-workspace.yaml` → `allowBuilds`), which it does on the Pi in ~40 s.
- **Capture health — the guard against silent loss**: `CaptureHealth` (in `audio.ts`, unit-tested) counts consecutive bursts where `burstCapturedNothing()` holds (`packets > 0 && bytes === 0` — received audio, wrote none; distinct from a speaker who simply said nothing). At `CAPTURE_FAILURE_ALARM_AFTER` (3) it fires **once per session**: `minutas.capture_broken` at error level, a `sendAdminAlert`, **and a warning posted into the voice channel itself** so the room can act. Recording continues regardless — a false alarm must never be what stops an assembly being minuted. This exists because on 2026-08-16 the only evidence of total capture failure was warn-level log lines nobody was reading.
- **On-disk session layout** (`data/minutas/sessions/<id>/`, id = CDMX `YYYYMMDD-HHMM-xxxx`): `session.json` (manifest: channel, starter, participants), `bursts.jsonl` (one line per burst **written when the burst OPENS** — the timeline start is what matters and must survive a crash), `chat.jsonl`, `transcripts-live.jsonl` (the live-transcription ledger, appended as batches complete), then per batch `audio/batch-NNN-<speaker>.wav` + `transcript/batch-NNN-<speaker>.json` (whisper raw), and at finalize `transcript.jsonl`, `draft.md`, `transcripcion.md`, `minuta.md`.
- **Crash/restart resilience**: sessions row in SQLite (`minutas_sessions`: active → processing → done/failed). A row still `active`/`processing` at boot means the last process died mid-session — the `start()` sweep finalizes it from whatever the dir holds (drafts + minutes still publish). `dispose()` deliberately leaves rows `active` for that sweep.
- **Transcription is local whisper.cpp** (`data/minutas/bin/whisper-cli` + `ggml-small.bin`, built by `scripts/setup-minutas-whisper.sh` — venv-supplied cmake, zero system installs): community audio never leaves the Pi and there's no per-minute meter. `-l es -oj`, **one whisper process at a time** (serialized queue) so a long assembly can't OOM the box, and the child is `nice`d to `WHISPER_NICE` (10) so an hour of transcription doesn't starve the Discord event loop. Transcriber missing → sessions still record; bursts stay untranscribed (logged, kept).
- **Cost model — measured on real assembly audio (Pi 5, `small`, 2026-08-17), not estimated:**

   > **`wall ≈ 8.5 s per burst + 0.82 × seconds of audio`**

   Fitted from 2 s→9.9 s, 10 s→12.8 s, 30 s→30.5 s, 197.6 s→168 s. Validated end-to-end against the 2026-08-16 assembly: 155 bursts + 3976 s of audio → 76 min predicted vs **~74 min observed**. Two consequences worth internalizing:
   - **Per-burst overhead dominated 29% of that wait** (155 × 8.5 s = 22 min), because whisper pads every invocation to a 30 s window. That is what the live batching bullet below eliminates — the model still labels leftover whisper at finalize (`minutas.finalize_started`).
   - `MINUTAS_WHISPER_THREADS=2` is set in `.env` (user decision 2026-08-17, made viable by live batching). Benchmarked on the same 197.6 s clip: `-t 4` = 166 s, `-t 3` = 168 s, `-t 2` = 203 s. Two threads cost ~21% throughput but leave **two cores free while whisper runs alongside a live recording** (gateway + burst ffmpeg decodes + whatever else the Pi serves) — and with concatenation, 2 threads still transcribe faster than people talk (0.93× realtime measured on real audio), so the live pipeline never falls behind. Not a thermal lever at any thread count.

- **Thermals (measured, and they close off the obvious "just make it faster" moves)**: an hour of all-core whisper puts the Pi 5 at **84.5 °C with the fan already maxed** (`pwm1` 250/250 = the firmware's top cooling level; forcing 255 gains 22 RPM), soft-limit bit active (`throttled=0xe0008`), clock pulled to **2.15 GHz** from 2.4. Idle recovers to 61.5 °C / 2.4 GHz / fan 2-4. So: **do not overclock** (no thermal headroom to spend) and **do not move to `medium`/`large`** (~3.5×/~7× the compute on a box already throttling). A quantized `small-q5_1` is the only model-side lever with headroom.
- **Burst length floor**: `MIN_BURST_BYTES` is **0.5 s** (was 1 s). At 1 s the 2026-08-16 assembly discarded **72 of 228 captured bursts (32%)**, including real short answers. Lowering it costs a full 30 s whisper window per extra burst — a deliberate trade of time for completeness, since a minutes tool dropping a third of the turns is the worse failure.
- **Draft → minutes**: whisper segments land on the session timeline by `burst.startedAtMs + segment offset`; `buildTimeline` merge-sorts speech + chat (💬-marked) and folds same-speaker gaps <4 s. The LLM pass (`generateMinutes`, effort **`low`** = thinking off since the v2.0.0 migration — no tools) writes the acta with the exact section structure `Resumen / Temas tratados / Acuerdos y decisiones / Compromisos` — **no chat dump**. 💬 lines stay in the draft as context (a link, a name, a correction) so the writer can understand the spoken discussion; they are never quoted or listed. Jokes, memes and hyperbole are not acuerdos (2026-08-18: «tomamos palacio nacional» landed as chat record — `stripMinutesChatSection` is the fail-closed guard if the model still emits `## Comentarios del chat`). Names in plain text (never `<@id>`), `SPANISH_VOICE_RULES` enforced. Drafts up to MINUTAS_SINGLE_PASS_CHARS (default 900k characters) use one pass; larger drafts use 240k-character blocks and a final merge.
- **Publishing** (`publisher.ts`) — **ONE message** since 2026-09-23 (v2.2.0, user request: the full acta chunked into the channel was flooding #minutas-de-asambleas — a 2½-hour assembly was several consecutive posts). `renderMinutesSummaryPost()` = `# 📜 Minuta — <título>` header (canal/fecha/duración/participantes) + **only the `## Resumen`** + a pointer line that counts what's in the file ("📎 La minuta completa (temas tratados, 3 acuerdos y 2 compromisos) va en el archivo adjunto **minuta-<id>.md**"), capped under Discord's 2000 chars (an over-long Resumen is cut on a sentence; no Resumen → the first paragraph). The complete acta is the attached `minuta-<id>.md` (byte-identical to `minuta.md` in MinIO). `allowedMentions: {parse: []}` (an acta must never ping). Tests: `__tests__/summary-post.test.ts`. The full transcript is **archive-only** (user decision 2026-08-17): a near-verbatim who-said-what stays out of the channel and lives as `transcripcion.md` in the session's MinIO prefix, where moderation can pull it to check an acta. The voice channel chat gets the completion note with the URL.
- **Leave always finalizes now** (2026-08-19): live transcription keeps pace during the meeting, so `/chopperbot-leave` (and auto-end / boot sweep) runs leftover whisper (the last un-flushed tail) + the LLM pass immediately. The old nightly window (`MINUTAS_HEAVY_WINDOW_*` / `transcribe_after` timers, aligned with IG quiet hours 01–08) is gone — it existed when finalize meant re-transcribing the whole assembly. The `transcribe_after` column remains on the row (unused). Journal: `minutas.finalize_started`.
- **MinIO structured archive**: on finalize everything uploads to `minutas/<guildId>/<yyyy-mm-dd>/<sessionId>/` (audio as WAV, no PCM). Local dir is deleted **only** after a complete upload; storage down → local kept (the only copy), warn logged. Row gets `minio_prefix`, `summary_message_id`, stats.
- **Admin surface**: `config_minutas` — `status` (output channel, transcriber availability, active recording, last 5 sessions), `set_output_channel {channel_id}`, `end_session` (stops this guild's recording = `/chopperbot-leave`). Wired via `configCap.attachMinutasAdmin()` in `app.ts`. Env seeds: `MINUTAS_OUTPUT_CHANNEL_ID` (first boot only, DB wins after), `MINUTAS_WHISPER_BIN/MODEL_PATH/LANGUAGE/THREADS`, `MINUTAS_MAX_SESSION_MINUTES` (300 — forgotten-session backstop).
- **E2E proof**: `npx tsx scripts/verify-minutas.ts` — synthesizes two Spanish speakers (gTTS → wav → 48k PCM → Opus frames, the exact receiver shape), proves opus→PCM→whisper standalone, joins the real **Sala de echar desmadre**, drives the real burst/chat pipelines, and runs the real finalize (whisper + DeepSeek + MinIO + the #minutas post), asserting DB state, the MinIO key layout, draft attribution and the published message. Spends a little DeepSeek budget and posts a clearly-marked PRUEBA. Setup: `bash scripts/setup-minutas-whisper.sh` (idempotent).
- **Real-event proof (2026-08-17, session `20260816-2008-cf2b`)** — what the synthetic e2e above could **not** cover, because injecting receiver-shaped frames bypasses the network and decode path entirely. A real 81-min assembly ("caliban y la bruja", 🎙️ Sala de Eventos 🎙️): real UDP receive + `aes-256-gcm` decrypt (verified by watching the packet rate go 2/s → 36/s at first speech), **3 live speakers separated correctly**, 250 bursts / 67.1 min of audio / 70 chat lines / 8 participants, accurate Spanish transcription, correct acta sections and attribution, 407 files (125 MB) archived to MinIO, both files attached to the post. It is also what **found the opusscript leak** — the lesson being that a short test cannot surface a resource exhaustion bug, so any future decode/capture change wants a long session before it is trusted.
- **Test fixture from that real assembly — use it instead of guessing.** The full session is preserved at **`pi:~/ChopperBot-private-assets/minutas-fixture-20260816-2008-cf2b/`** (123 MB; `README.md` there documents layout, caveats and recipes), mirrored in MinIO under the session's normal prefix. It holds 155 real 16 kHz WAVs (66.4 min, 3 speakers), the whisper raws, `bursts.jsonl` with every `startedAtMs`, `chat.jsonl`, `draft.md` and the known-good `minuta.md`. A `sample/` subdir has 5 clips (11 MB) spanning 1 s → 276 s for quick iteration. **Private, never committed** — it is identifiable community audio and this repo is public; synthesize with `verify-minutas.ts` if you need something committable. Three caveats that decide whether it can answer your question: it has **no sub-1 s bursts** (only bursts passing the old 1 s floor were ever written as WAV, so it cannot validate the current 0.5 s floor), **no raw Opus packets** (so it exercises transcribe→minutes, not receive/decrypt/decode — use `audio.test.ts` for that), and it contains the decoder failure itself (250 bursts opened, 228 written, 155 transcribed). Benchmark against **real speech, never a synthetic tone**: a tone gives the decoder nothing to emit and runs ~5× too fast, which is precisely how the first cost estimate went wrong.
- **Live transcription + burst concatenation** (`live.ts`, shipped 2026-08-17): finished bursts stream into a `LiveTranscriber` that batches them **strictly per speaker** (Discord's exact separation is never re-derived — a segment can only land on a burst of the voice it came from) and runs whisper DURING the meeting, one invocation per batch instead of per burst. A speaker's batch flushes at `LIVE_FLUSH_AUDIO_SEC` (45 s) pending audio or `LIVE_FLUSH_MAX_BURSTS` (8); bursts join with `BATCH_GAP_MS` (1 s) silence; segments map back to the timeline by concat offset — each goes to the burst it **overlaps most**, one inside a join gap or past the file end goes to the nearest burst, and only whisper's stock hallucinations are dropped (`isWhisperHallucination`: `[Música]`-style tags, Amara/subtítulos, «¡Suscríbete!», «próximo vídeo»). The earlier "midpoint in a gap → drop" rule was retired 2026-09-23 on evidence — see the audit bullet below. Misattribution is impossible either way (a batch is one speaker). **Crash safety is the ledger** (`transcripts-live.jsonl`): every transcribed batch appends its bursts there first; finalize is ledger-first and batches only the remainder, so the post-meeting work is normally just the last un-flushed tail + the LLM pass — **the minute lands minutes after the session, not an hour** — and a crash at any point costs at most one batch of re-work. A failed live flush is logged (`minutas.live_batch_failed`) and NOT retried live: the bursts stay unledgered and finalize picks them up — the head start is lost, the audio never. Proven on real fixture audio at `-t 2`: 198.3 s / 3 bursts → one call, 185 s wall = **0.93× realtime, keeps pace with a live meeting**. Proven again on the 2026-08-18 assembly (`20260818-2003-736c`, ~2h 34m, 25 participants, 331 bursts / 1100 chat): live kept pace; a Discord shard reconnect mid-session did **not** drop capture; leftover whisper at leave was ~2 min. Journal: `minutas.live_batch_transcribed`.
- **Unit/integration**: `npx vitest run src/capabilities/minutas` — store lifecycle, timeline merge/render, block splitting + prompt contract, the command gate (mod role / Administrator / non-mod / DM / raw-API member shapes), and the full finalize pipeline against a fabricated session dir (real ffmpeg + SQLite, fake transcriber/storage/Discord). Also `audio.test.ts`: `CaptureHealth` (fires once at the threshold, resets on recovery), `burstCapturedNothing` (empty-vs-silent), real Opus round-trips through `recordOpusStreamToPcm` including corrupt packets mid-stream, a fully-garbage burst, and **80 sequential bursts** — that last one is the leak regression guard, since the old decoder died at ~55. Journal: `minutas.session_started`, `minutas.burst_recorded`, `minutas.session_closed`, `minutas.finalize_started`, `minutas.transcribed`, `minutas.finalized`, `minutas.minio_uploaded`, `minutas.command_denied`, `minutas.sweep_interrupted_session`, `minutas.alert`, and for capture health `minutas.capture_broken`, `minutas.opus_decode_errors`, `minutas.opus_decoder_rebuilt`.

- **2026-09-23 audit round (v2.2.0) — evidence from all 8 real sessions** (MinIO archives + journal; whisper A/B on real clips at `-t 2`). Shipped:
   - **Finalize no longer re-transcribes running live batches.** `beginFinalize` used `live.forget()` and read the ledger immediately, so batches still running at `/chopperbot-leave` were planned AGAIN: 2 / 9 / 115 / 25 / 12 duplicated bursts across the five most recent sessions, **~43% of all leave→post whisper time** (0922: a 345 s live batch finished 4 s after leave, then finalize re-ran those bursts in a 521 s batch). Now `LiveTranscriber.drain(dir)` awaits the session's in-flight batches first; `minutas.finalize_started` logs `drainedMs`. Expected: 0922-class sessions ~14 → ~6 min leave→post.
   - **Straddling speech is kept.** The midpoint rule dropped 187 of 6,472 segments, ~110 of them ≥10 words and only ~9 real hallucinations — «Y abstención.» (a vote option), «la segunda semana de octubre…» (a proposed date), a whole 29 s opening statement. Replaced by max-overlap mapping + a hallucination blocklist (`__tests__/live.test.ts`).
   - **Whisper initial prompt** (`--prompt`, `buildWhisperPrompt`): `WHISPER_VOCABULARY` (RevZ, Comité Ajolote, Kiosco Morisco, el Chopo…) + session title + participants' names with decoration stripped, read from `session.json` — which is now rewritten whenever a new participant first appears, so live batches see the roster. Evidence: «Repseta» for RevZ ~20× (reached a published minuta), one member's nickname misheard as a Spanish word 29× (5× in one minuta, under Compromisos), «QIOS Comorisco». A/B on 3 real clips: every targeted term corrected, punctuation better, wall time unchanged. Side effect: longer segments — which is why the overlap mapping above matters.
   - **Stable names.** The first name seen for a user id wins for the whole session; later ones become `aliases` in `session.json` and a "Alias vistos" line in the prompt (0818: one user id spoke under one nickname and later chatted under another, and the acta gave them two separate commitments).
   - **Chat capture** (`chatContentOf`): mentions → `@Name`, custom emoji → `:name:`, newlines folded, `[imagen]` / `[archivo: x]` / `[sticker: x]` / `[encuesta: «…»]` instead of an empty line (262 of 3,472 lines were empty); **poll tallies are fetched from Discord at finalize** (`withPollResults`: "resultado final: Sí (14 votos), No (3 votos)") — the assemblies vote with polls and the acta only knew a result if someone read it out.
   - **Minutes prompt**: participant-list spelling wins over the heard name; no outside knowledge («Calibán y la bruja» must not become «de Silvia Federici»); a ±6-week **date → weekday table** in the meta block (0818 turned «sábado 29» into «sábado 29 de septiembre», a Tuesday); **privacy** — personal disclosures (salud mental, terapia, violencia) and harassment-case details are summarized neutrally without names (0831 and 0922 published both) — _a policy choice, easy to revert in `buildMinutesSystemPrompt`_; the map-reduce merge now fuses repeats across parts and never says «bloque»/«parte».
   - **Not shipped (needs a benchmark first):** VAD (`--vad` + the Silero v6.2.0 model already in the whisper.cpp checkout): one 60 s clip ran 80 s → 44 s and lost a «¡Suscríbete!» hallucination, but also lost punctuation and one word. **Open:** single-pass now covers assembly-sized transcripts under the configured 900k-character cap.

## Failure modes seen in the wild

| Symptom                                                               | Cause                                                                                                                                                                           | What to do                                                                                                               |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Bursts keep opening (`bursts.jsonl` grows) but no `.pcm` files appear | Decoder wedged. Pre-2026-08-17 this was the opusscript heap leak; it should now be impossible.                                                                                  | `minutas.capture_broken` fires and posts in-channel. Restart the bot to reset; audio before the failure is safe on disk. |
| Session live, zero `.pcm`, nobody complaining                         | Nobody has spoken yet, **or** the meeting's audio is inside a screen-share/Go-Live stream — bots receive microphones only, never stream audio.                                  | Check the incoming packet rate: idle/keepalive is ~2–7/s, one live speaker ~36–50/s.                                     |
| Minute is late by an hour+                                            | Unexpected now that live transcription keeps pace. Remaining work at leave is the last tail + the LLM pass (map-reduce if the draft exceeds the configured single-pass budget). | Check `minutas.finalize_started` leftover counts and `agent_turn` logs.                                                  |
| Bot at 84 °C, clock at 2.15 GHz during transcription                  | Expected. Fan is already maxed; the SoC protects itself.                                                                                                                        | Nothing. Idle recovers to ~61 °C. Do not overclock.                                                                      |
| Short answers missing from the acta                                   | Bursts under `MIN_BURST_BYTES` (0.5 s) are skipped at transcribe time.                                                                                                          | Expected trade-off; lower the floor only if willing to pay a 30 s whisper window per extra burst.                        |

## Recording authority

Start/stop uses the effective **moderation** tier, including configured moderation roles, and rejects bot interactions. Gestión retains events/calendar authority but cannot record. Console administration also remains moderation-only. Proof (2026-10-04, v2.5.0): Gestión-only join/leave refused and moderation allowed in mocked-effect tests; full suite 1,407 tests, typecheck/build green, service active and slash commands registered after restart. No real recording was started for verification.

Public conduct privacy (v2.6.0): publicMinutes checks spoken transcript, generated body and session metadata for conduct/moderation markers. Chat-only lines do not trigger the speech check; model-emitted conduct still does. Flagged meetings publish a neutral notice with no participant identities, original title or identifying details in either summary or attachment. The complete acta is saved as minuta-interna.md in the internal MinIO/local archive; minuta.md is the redacted public document. This deliberately redacts the whole public acta for mixed conduct meetings rather than relying on the model to partition named incidents correctly. It is conservative marker-based detection, with the prompt also requiring conduct labels and no names; human review remains important for unfamiliar phrasing. No private-channel post is sent, so no audience exception or setting change is needed.

Proof (2026-10-04): synthetic named conduct transcript leaves neither identity in the public summary/header/attachment; an assembly-sized synthetic draft invokes one complete low-effort pass with a mocked model. 1,426 tests/typecheck/build green and deployed service active; no real meeting or publication was used for verification.

Slash-command failures share the per-channel identical-error guard (v2.6.1): one generic error per five minutes. A suppressed interaction is still acknowledged ephemerally and its temporary reply removed; recordings and finalize behavior are unchanged. No real recording was used to test failures.
